# 终端交互实现与迁移边界

> 本文旧版“已统一迁移到 Bubble Tea”的声明与当前运行代码不符，不作为已完成迁移的依据。本轮改造在现有终端编辑器上完成，没有切换 UI 框架。

## 当前实现

- 交互入口是 [repl_loop.go](../cli/cove/repl_loop.go)，输入、固定输入区、候选选择和 Agent 面板使用 [LineReader](../internal/repl/readline.go)。
- 流式输出通过终端自身滚动区域与光标报告定位，保留终端原生滚动和复制，不接管整个屏幕。
- 命令逻辑由共享 frontend 分发；headless 保留同步逐行输入和文本输出，不打开交互选择区。
- 终端不支持原始输入或固定区域时，保留已有降级路径。
- 需要用户确认的命令（`/undo`、`/history clear`）用非阻塞确认框：命令打印框后立即返回，主循环把下一行交给待定的确认（`confirmThen`/`takePendingConfirm`，底层 `repl.ArmPrompt`）；斜杠命令运行在输入循环上，不能阻塞等输入。状态行临时提示 `repl.SetHint`、Esc 清空后 Ctrl+Z 恢复、掩码输入 `ReadSecret` 同属本层。

## 本轮交互改进

1. 普通空闲状态保持安静，任务处理、等待回答或面板选择时显示简短易懂的状态，附件仍可见；未变化时不重绘。
2. 命令候选使用纵向列表，显示说明，Enter 接受候选但不直接执行。
3. Agent Map 默认不抢方向键；空输入 Tab 或 Shift+Tab 切换焦点，自动刷新最多每两秒一次。
4. 空闲交互模式的历史会话支持搜索、元数据预览和选择；保留项目过滤、稳定会话 ID 及文本编号路径。
5. 交互模式的长实时工具输出限制预览，工具结果全文和 `/x` 入口保留，headless 不折叠实时输出。
6. 审批操作与授权范围在输入区附近持续展示，原有单键回答、拒绝和授权政策不变，结束后清理预览。

## 后续迁移约束

- 不以更换框架作为交互完善的前提。
- 保留运行中追加指引、审批答案分流、草稿、任务队列和 headless 行为。
- 如确实需要全屏视图，再单独评估焦点、滚动复制、窗口尺寸、Windows 和 SSH 的兼容性。
- 新交互首先验证候选接受与执行的区别、取消与 EOF、窄终端布局、并发输出和非交互降级；不得仅用编译通过宣称迁移完成。
